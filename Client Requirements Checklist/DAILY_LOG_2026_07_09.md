## 2. New Feature: "Who's About to Buy" Tracking
Built a way to see, for any customer who has created an account, what they've added to their cart — even if they haven't checked out yet.

**Why it matters:** Right now the admin can only see customers *after* they place an order. This closes that gap — a customer with zero orders but three items sitting in their cart is a warm lead worth reaching out to, and now that shows up directly on the Customers page and on each customer's detail page.

**How it works:** When a signed-in shopper adds something to their cart, it's logged. If they go on to actually buy it, it's automatically marked "converted" so the admin isn't left thinking someone still has an item in their cart after they've already purchased it. Shoppers who aren't logged in are never tracked — this only applies to registered visitors.

A deep review at the end caught two real bugs before they shipped: purchases of color-variant products weren't being matched up correctly (so a completed sale could have kept showing as "still in cart" forever), and re-adding a previously-bought item could have wiped out its purchase history. Both were fixed and re-verified before merging.

**One step still needed:** a one-time database setup script for this feature has been written but not yet run in Supabase. Nothing breaks until it's run — the feature will just show nothing until then.

## 3. New Feature: Visitor Location Map
Added a world map to the Analytics page showing where site visitors are actually coming from — a bubble on the map per city, sized by how many visits came from there, over the last 30 days. This uses geographic data that Vercel (the hosting provider) already provides for free per visit — no new paid service involved.

**One important step needed before this goes live:** a second database setup script (separate from the one above) needs to be run in Supabase *before* this code is deployed to the live site. If the code goes live first, every single visitor-tracking record on the whole site — not just the new map — would silently stop saving until the script is run. This is flagged as the top priority for the next deploy.

## 4. Production Build Was Broken — Found and Fixed
While setting up the map, a live deployment on Vercel failed to build at all. Root cause: the mapping library added for the map only officially supports an older version of React than this site runs on. Locally this had been worked around by hand, but that workaround was never saved anywhere, so Vercel's own build didn't know about it and failed every time.

Fixed by adding a small permanent config file so the override applies automatically on every future build, not just the one done by hand. Verified with a full clean install matching exactly what Vercel does — confirmed working.
