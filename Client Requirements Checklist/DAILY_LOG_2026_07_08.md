## 8. Settings Page — Real Security Bug Found and Fixed
Entire Settings page (Store Details, Regional, Notifications, Change Password) looked functional but saved nothing — a refresh reset everything.

Most serious: Change Password checked input against a hardcoded fake value, unrelated to the real login password. A "successful" change here never actually changed the real credential. Fixed:
- All sections now save for real and persist after refresh.
- Change Password now updates the real login credential via the same secure method the login screen uses.
- Added attempt-limiting on password changes, matching the login screen's existing protection.
- Removed 12 unused leftover test/demo code blocks.

One manual step (a database setup script) was required and has been completed — confirmed working live.
