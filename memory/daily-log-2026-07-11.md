## 5. Admin Login OTP "Expired" Bug — Root-Caused and Fixed, Scott Confirmed
Reported by Scott via email (relayed through Peter manually entering a code from his own inbox — itself a symptom). Ran through superpowers:systematic-debugging properly rather than jumping to a fix. **Root cause:** `pendingOtps` (`lib/admin/auth.ts`) was a plain in-memory `Map` — incompatible with Vercel serverless, where a login request and the following verify/resend request can land on different, memory-isolated instances, so the OTP record was simply gone (not actually expired) by verify time. Confirmed against a working reference pattern already in the same codebase (`lib/admin/ratelimit.ts` uses `Redis.fromEnv()` correctly for exactly this kind of cross-invocation state). Fixed by moving the OTP store to Redis (`getPendingOtp`/`setPendingOtp`/`deletePendingOtp`), and fixed a related silent bug where the incremented attempt counter wasn't being persisted (only worked before by accident via in-memory object mutation).

**Secondary bug fixed in the same pass:** the masked-email shown during login always displayed the *first* address in `ADMIN_EMAIL` (Peter's own personal Gmail, not Scott's) — this was the "another email address there" confusion Scott reported. Replaced with a generic message per user's explicit request: "If your email is associated with this account, you'll receive a code."

Scott replied "That worked!" after retrying — confirmed live.

## 6. AdminTopbar Z-Index Stacking Bug
User reported the profile dropdown appearing to be covered by/covering the Product edit page's own sticky action bar inconsistently across two related questions. First instance (dropdown covering page buttons while open) was explained as standard, expected dropdown behavior — no fix needed, user agreed. Second instance (search dropdown/profile menu being covered *by* the page's sticky bar) was a real bug: `AdminTopbar.tsx`'s `<header>` was `fixed ... z-20`, while `products/[id]/page.tsx` and `products/new/page.tsx`'s sticky sub-header used `z-30` — since the header establishes its own stacking context, its internal `z-50` dropdowns were capped below the page's `z-30` sibling. Fixed by raising the header to `z-40` (clears the only two `z-30` sticky bars in the app, confirmed via grep across `app/admin`).
