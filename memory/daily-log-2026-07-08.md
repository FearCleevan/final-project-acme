# Daily Log — July 8, 2026

## What got fixed today, in plain terms

**1. Admin search was showing fake demo results.**
Typing in the admin dashboard's search bar (top of every admin page) was matching against old placeholder test data instead of the real store — so search results pointed to products that don't exist and gave "Product not found." Rebuilt it to search real, live Shopify data instead: products (by name, SKU, ID), orders (by order number, customer, **and tracking number/carrier**), and customers. Also fixed a broken link where an order number with a "#" in it would send the browser to the wrong place.

**2. The whole Settings page was fake — and one part of that was a real problem.**
Every single section of Admin → Settings (Store Details, Regional preferences, Notifications, and Change Password) looked like it saved successfully — spinner, green checkmark, "Saved" — but **none of it actually saved anywhere**. Refreshing the page reset everything back to hardcoded placeholder text.

The serious part: the "Change Password" box was checking your typed password against a fake hardcoded value baked into the code, not your real admin login password. If anyone had gone in there and "changed" the password, believing it worked, **the real login password would never have actually changed** — false sense of security.

This is now fully fixed:
- Store Details, Regional, and Notifications now save for real to a new database table and reload correctly after a refresh.
- Change Password now genuinely changes your real login password, using the same secure method (bcrypt + Redis) the actual login screen uses — and it's now rate-limited too, so it can't be brute-forced by someone who got hold of a logged-in session but not the real password.

**3. Built a reusable "dashboard starter kit" document.**
Since dashboards keep coming up across projects (this one uses Next.js, another uses Vite), wrote up a portable template capturing the sidebar/topbar/stat-card/table layout as plain React + Tailwind, with no framework-specific code — so the next dashboard build doesn't start from scratch.

## What still needs a small step from you
The new Settings table required one manual step in Supabase — running a SQL file in the dashboard. That's been done and verified live (queried the real table directly to confirm). Everything is otherwise ready — code changes are sitting in the working directory, not yet committed (as usual, that's left for you to commit yourself).
